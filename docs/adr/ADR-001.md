# ADR-001: Protocol injection over monkeypatching

**Status:** Accepted
**Date:** 2026-03-01

---

## Context

Netcheck makes system calls through several different mechanisms: subprocess
commands (`ip`, `resolvectl`, `mmcli`, `lspci`, `lsusb`), sysfs file reads,
and HTTP requests to the ipinfo.io API.  Every module that performs I/O is
therefore a unit-testing problem: tests that spawn real processes are slow,
environment-dependent, and cannot exercise failure paths predictably.

The standard Python solution to this problem is `unittest.mock.patch`, which
replaces a named attribute in a module's namespace at test time.  The two
common alternatives are dependency injection (pass the dependency in as an
argument) and a seam at the I/O layer (abstract the I/O behind an interface).

`unittest.mock.patch` has a well-known failure mode: it patches names, not
objects.  If the code under test has already imported `subprocess.run` into
its own namespace with `from subprocess import run`, a patch targeting
`subprocess.run` does not affect the copy already held by that module.  This
makes patching fragile in proportion to the number of import styles in use
across a codebase.  More fundamentally, patching is invisible at the call
site: there is no indication in the production function signature that it
depends on subprocess, which makes the dependency implicit and the function
harder to reason about.

---

## Decision

Every module that performs I/O accepts its dependency as a Protocol argument:

- **`CommandRunner`** (`src/netcheck/utils/command.py`) -- one method: `run(cmd: list[str]) -> str | None`.  Every module that runs system commands receives an instance of this rather than importing `subprocess` directly.
- **`SysfsReader`** (`src/netcheck/utils/sysfs.py`) -- methods for reading sysfs files, resolving symlinks, and walking parent paths.  Used by hardware detection.
- **`HttpClient`** (`src/netcheck/utils/http.py`) -- one method for making GET requests.  Used by egress detection.

Production code receives `SystemCommandRunner`, `SystemSysfsReader`, and
`SystemHttpClient`.  Tests inject `FakeCommandRunner`, `FakeSysfsReader`, and
`FakeHttpClient` from `tests/fakes.py`.  These fakes record calls and return
fixture data; they implement the same Protocol interface as their production
counterparts.

`unittest.mock.patch` is banned in this codebase except where explicitly
documented in the Approved exceptions section below.

The Protocol approach is enforced by Python's structural subtyping: any object
whose method signatures match the Protocol satisfies it, without requiring
explicit inheritance.  This means fakes do not need to inherit from anything;
they just need to have the right methods.

---

## Consequences

**Positive**

- Every production function that touches the OS has an explicit, typed seam
  in its signature.  The dependency is visible to callers, to mypy, and to
  readers.
- Fakes are plain classes.  They do not use any mocking framework and do not
  depend on internal Python import mechanics.  They are straightforward to
  read and extend.
- Failure paths (command not found, timeout, HTTP error, sysfs missing) are
  tested by returning `None` or a specific value from the fake; no patching
  of exception-raising behaviour is needed.
- mypy can verify that every fake correctly implements its Protocol.

**Negative / trade-offs**

- Every new I/O dependency requires three things: a Protocol definition, a
  `System*` production implementation, and a `Fake*` test implementation.
  This is more upfront work than adding a `patch` call to a test.
- Modules that currently call `subprocess` directly cannot be made testable
  without first refactoring them to accept a `CommandRunner`.  This is an
  investment, not a shortcut.

**Boundary**

This pattern applies to I/O at the OS boundary.  Pure computation modules
(`src/netcheck/output/formatters.py`, `src/netcheck/core/`) have no I/O dependencies
and require no injection.

---

## Boundary: composition root testing

`src/netcheck/__main__.py` is the composition root.  It is the one place in the
codebase where concrete implementations (`SystemCommandRunner`,
`SystemSysfsReader`, `SystemHttpClient`) are instantiated directly and wired
together.  The Protocol injection discipline cannot apply here by definition:
the composition root is the place where the chain of injection begins.

Tests for `main()` in `tests/unit/test_main.py` use `pytest.monkeypatch` to
replace module-level attributes (e.g. `netcheck.__main__.collect_network_data`)
at the composition root boundary.  This is the one approved use of attribute
replacement in the test suite, and it is structurally different from the
`unittest.mock.patch` pattern that is banned:

- It targets the composition root only, not internal call sites.
- It replaces a named attribute at the module level, which is the correct
  seam at the entry point.
- It does not affect any module below `main()` in the call stack; those
  modules are tested via injected fakes in the normal way.

`unittest.mock` remains banned everywhere except in `test_http.py` (see
Approved exceptions below).  `pytest.monkeypatch` is permitted only for
`main()` tests and must not be used as a substitute for Protocol injection
in any other test module.

---

## Approved exceptions

### `tests/unit/utils/test_http.py`

`SystemHttpClient` is the thin production adapter whose sole job is to call
`requests.get` and translate its results and exceptions into the `HttpClient`
Protocol.  `FakeHttpClient` exists to spare every caller of `HttpClient` from
needing to know about `requests` -- but it cannot be used to test
`SystemHttpClient` itself: the fake replaces the adapter, not the library the
adapter wraps.

To verify that `SystemHttpClient` correctly calls `requests.get`, handles its
exception hierarchy, and drives the retry-and-backoff loop, `requests.get`
itself must be replaced at test time.  `unittest.mock.patch("requests.get", ...)`
is the correct tool: `http.py` imports `requests` as a module (not a name from
it), so the patch target is unambiguous and the fragility described in the
Context section does not apply.

Any new use of `unittest.mock.patch` requires the same written justification
in both the test module docstring and in this section.  One approved exception
does not lower the bar for a second.
